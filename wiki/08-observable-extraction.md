# Stage 08: observable extraction

`python 08_observable_extraction/beam_asymmetry.py --help` exposes the standalone CLI. `scripts/run_pipeline.py` invokes it after reconstruction and measured calibration. The loader accepts compatible `raw` and `raw_bdt` products, selected beam profile, curated manifest, quality policy and calibrated flux. POL1 is vertical, POL2 horizontal; BREM is an unpolarized control. A usable run requires the validated flux triplet.

The default profiles are UV `[1.10,1.20,1.30,1.40,1.50]` GeV and VIS `[0.9313,1.10]` GeV, with explicit energy configuration supported. Pair masses and laboratory azimuths are formed for pπ⁰, pη and ηπ⁰. The same event contributes to all three projections.

For normalized yields yV=NV/FV and yH=NH/FH, the ratio is `(yV−yH)/(PH*yV+PV*yH)`. The nominal cosine fit and its low-p-value offset/sine diagnostic retain the existing conventions. The [finite-bin correction](finite-bin-correction) scales ratio Sigma and its errors exactly once by the approved divisor for 8/12/16 bins. `--best-binning` selects among those fits per point.

New extraction uses uniform azimuth bins centered at zero: the default 12 bins have edges from -15 to 345 degrees. Supported 8/16 grids use the same center convention. Angles wrap into the histogram interval without a physical phase shift or event loss. The literal divisors remain 0.9003, 0.9549 and 0.9745. Historical zero-edge products remain readable, but composition rejects mixed origins as well as incompatible correction or selection definitions; reading never upgrades historical results.

The conditional likelihood retains event run/strip exposure strata, physical Sigma domain and asymmetric intervals. It is not rescaled by the finite-bin divisor. Zero-yield exposures in the inclusive run universe must remain represented; `--by-period` uses reconstruction cutflow or an explicit universe manifest to compose exact catalog periods and pooled results.

Sideband/signal-MC inputs support background-fraction correction. Systematic components and run bootstrap can produce covariance products, but available machinery is not a completed uncertainty budget. The default launcher uses zero bootstrap replicas. Paired diagnostic bootstrap is distinct from covariance adopted for publication. Non-estimable bins remain marked, not zero-filled.

[Application owners](https://github.com/AntoninoFulci/GRAAL_Analysis/blob/main/08_observable_extraction) separate `workflow`, `period_workflow`, `extraction`, `extraction_background`, `extraction_systematics`, `core`, `io` and `plotting`. Outputs include `beam_asymmetry.root`, point/covariance metadata and diagnostic/publication PDFs. The [core-versus-tail candle test](core-tail-candle-test) is an additional stability extraction and does not replace the nominal result. Use [manual extraction and composition](commands-and-configuration) to rerun this stage on compatible saved inputs. The former theory implementation is [retired](09-theory); experimental extraction remains active.

The default launcher enables the Gaussian candle in eta pi0: a correlated Gaussian plus constant pedestal fitted to raw candidate masses defines the inclusive 50% Gaussian-probability ellipse. The default nominal-mass +/-0.05 GeV rectangle is the fit window, not the tight selection. Core and tails retain all finite candidates without equalizing observed counts; the full nominal `raw_bdt` remains unchanged. Standalone `--candle-gaussian` enables this mode, while a width alone preserves the explicit legacy rectangle. The [candle operating page](core-tail-candle-test) provides a Stage-08-only rerun command and output definitions.

Gaussian outputs add the ellipse and stored-fit projections, full/core/tails physical quality controls, and `candle_comparison.json`. Comparison replicas default to zero. Optional `--candle-comparison-replicas N` requires at least two and `--by-period`: shared run draws yield conditional full/core and core/tails covariance diagnostics while holding the contour fixed. These are not final errors or a contour-uncertainty estimate. No balancing weights or cross sections are introduced; mass-distribution balancing remains a sketch.

Selection diagnostics share extraction and paired-run bootstrap through `comparison`; their gate, mass and track commands retain their distinct selection and provenance policies. Common cutflow, angular retention and covariance-error calculations belong to `core.gate_comparison`, certified reconstruction reading to `io.reconstructed_events`, and comparison ROOT serialization to `io.root_output`. `plotting.comparison` initializes plotting only when rendering is requested. The original gate helper imports remain compatible, but the mass and track commands no longer depend on that CLI.

The single-result workflow writes its ROOT payload before rendering the result PDFs through a local reporting helper. Background and BREM controls remain beside their selection logic to preserve ordering; this separation does not change binning, uncertainties or output contracts.
